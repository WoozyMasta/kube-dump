# Ресурсы Kubernetes

Команда `resource` сохраняет объекты Kubernetes как YAML.

Перед записью kube-dump применяет профиль. Профиль выбирает объекты,
удаляет служебные поля и при включённом шифровании защищает значения.

Полный список параметров находится в [справочнике команд](../../cli.md#resource).

## Сохранение в каталог

```shell
kube-dump resource save dir ./backup
```

По умолчанию используется профиль `backup`.

Посмотрите содержимое встроенного профиля командой:

```shell
kube-dump profile show backup
```

Чтобы сохранить объекты без очистки и ограничений встроенного профиля,
укажите профиль `raw`:

```shell
kube-dump resource save dir ./backup --profile raw
```

По умолчанию сохранение ничего не удаляет:
объекты, исчезнувшие из Kubernetes или исключённые новым профилем,
остаются в каталоге.
Чтобы удалить файлы ресурсов, которые были сохранены ранее,
но больше не входят в текущую выборку, укажите `--prune`:

```shell
kube-dump resource save dir ./backup --prune
```

Для каталога, Git и S3 `--prune` выполняется только после полной сборки
и удаляет только пути из манифеста владения целевым хранилищем.
Каждый полный бекап обновляет этот манифест;
без `--prune` он сохраняет историю, необходимую для последующей очистки.
В каталоге и Git-бекапе он находится по пути
`resources/.kube-dump/ownership.yaml`.
Одно целевое хранилище соответствует одному логическому бекапу ресурсов;
для независимых расписаний используйте разные каталоги или S3-префиксы.
Для каталога и Git дерево сначала собирается во временном месте,
а S3 сначала загружает новое поколение и только потом переключает указатель.
При ошибке сборки или публикации
существующее содержимое целевого хранилища не меняется.
Без `--strict` сбор продолжает получать диагностику после предупреждений;
с `--strict` останавливается на первой ошибке сбора.

> [!CAUTION]
> Не размещайте в дереве бекапа произвольные пользовательские файлы.
> Они не входят в формат kube-dump и не управляются командами сохранения,
> очистки и преобразования.

## Сохранение в Git

Git удобно использовать для YAML:
изменения видны через обычный `git diff`, а история хранится самим репозиторием:

```shell
kube-dump resource save git ./backup \
  --git-remote-url git@example.com:infra/kube-backup.git \
  --git-branch main --git-commit --git-push
```

Git предназначен только для ресурсов.
PVC и контейнерные образы туда не сохраняются.

## Сохранение в S3

```shell
kube-dump resource save s3 --s3-uri s3://backup/prod/
```

Для S3-совместимого хранилища можно указать свой адрес и регион.
Точные флаги смотрите в [справочнике команд](../../cli.md#resource-save-s3).

## Архив

Если вместо дерева YAML нужен один файл, сохраните ресурсы в архив:

```shell
kube-dump resource save archive ./backup.tar.zst
```

Архив ресурсов можно сразу записать в S3:

```shell
kube-dump resource save archive-s3 --s3-uri s3://backup/prod/resources.tar.zst
```

Поддерживаются gzip и Zstandard. Архив можно целиком зашифровать AGE.

Подробнее: [Шифрование](encryption.md).

## Вывод без промежуточных файлов

```shell
kube-dump resource save stdout --profile backup
```

Например, передайте результат непосредственно в `kubectl`:

```shell
kube-dump resource save stdout --profile backup |
  kubectl diff -f -
```

> [!TIP]
> stdout используется только для данных команды. Логи туда не примешиваются.

## Разовый отбор

Для простого случая отдельный профиль писать не обязательно.

Чтобы сохранить объекты только одного пространства имён, укажите его:

```shell
kube-dump resource save dir ./backup --namespace production
```

Чтобы сохранить только определённые виды ресурсов, перечислите их:

```shell
kube-dump resource save dir ./backup \
  --resource deployments --resource configmaps
```

Чтобы отобрать объекты по метке, передайте селектор меток:

```shell
kube-dump resource save dir ./backup \
  --label-selector 'app.kubernetes.io/part-of=my-app'
```

> [!WARNING]
> Предупреждение сбора завершает команду сохранения ошибкой без публикации
> подготовленного результата. Добавьте `--strict`, если сбор должен
> остановиться раньше, а не продолжать получение объектов и диагностики.

Чтобы диагностика не росла без ограничений,
результат сохраняет не более восьми подробностей предупреждений.
В итоговом структурированном логе указывается точное число предупреждений
в поле `warnings` и число скрытых подробностей в поле `warnings_omitted`.

Размер манифеста владения ограничен 1 МиБ.
Слишком большой набор ресурсов завершается ошибкой,
а не создаёт неограниченный манифест для `--prune`.

Полный набор способов отбора находится в справочнике команд.

## Правила в профиле

Пример: сохранять ConfigMap, кроме автоматически созданного `kube-root-ca.crt`:

```yaml
apiVersion: kube-dump/v2
kind: Profile

metadata:
  name: production
  description: Production resource backup

resources:
  selection:
    resources:
      - core/v1/configmaps
      - '!core/v1/configmaps:kube-root-ca.crt'
```

Следующее правило удаляет служебные поля из выбранных ресурсов:

```yaml
resources:
  rules:
    - name: remove-runtime-state
      match:
        resources:
          - '*'
      remove:
        - .metadata.uid
        - .metadata.resourceVersion
        - .metadata.managedFields
        - .status
```

Полный формат профиля: [справочник профиля](../../profile.md).

## Шифрование отдельных полей

Профиль может указать поля, которые следует шифровать:

```yaml
resources:
  rules:
    - name: secret-data
      match:
        resources:
          - core/v1/secrets
      encrypt:
        - .data.*
        - .stringData.*
```

Ключи и способ шифрования передаются отдельно при запуске.

Подробнее: [Шифрование](encryption.md).

## Чтение сохранённых ресурсов

`resource cat` собирает сохранённые объекты обратно в поток YAML:

```shell
kube-dump resource cat dir ./backup |
  kubectl apply -f -
```

Если сохранённые поля зашифрованы, передайте файл с закрытым ключом AGE:

```shell
kube-dump resource cat dir ./backup --identity ./age-key.txt |
  kubectl apply -f -
```

Есть такие же команды для Git, S3 и архивов.

kube-dump не пытается заменить `kubectl`, Argo CD или Flux.
Его задача - сохранить данные и отдать обычный YAML.
